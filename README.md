# Mazh AI

Mazh AI is a rainfall-risk intelligence service with a React dashboard, a
FastAPI backend, a calibrated rainfall model, and a keypad-only Twilio IVR.
The IVR never uses speech recognition or an LLM. It reads fixed phrase
templates filled only with forecast/engine output.

For the complete architecture, API contract, ML pipeline, frontend flow,
voice/SMS behavior, configuration reference, and testing guide, see
[PROJECT_DOCUMENTATION.md](PROJECT_DOCUMENTATION.md).

## Render deployment

The repository includes `render.yaml` for a Singapore-region Python web
service. In Render, create the Blueprint from this repository and fill the
environment variables below. `render.yaml` intentionally contains names only;
secrets must be entered in Render's dashboard.

| Name | What it is | Where to get it |
|---|---|---|
| `ENV` | Runtime mode; use `production` | Set manually |
| `PORT` | Render-provided HTTP port | Set to `$PORT` or let Render provide it |
| `HOST` | Bind address | Set to `0.0.0.0` |
| `CORS_ORIGINS` | Comma-separated frontend origins | Your Vercel URL, plus local URLs if needed |
| `DATABASE_URL` | SQLite cache path/URL | Use `sqlite:///./data/cache.db`; cache is ephemeral on Render |
| `ML_ENABLED` | Enable the checked-in model | `true` |
| `RAIN_THRESHOLD_MM` | Training/target threshold in mm | `10` unless deliberately evaluating another target |
| `LLM_BASE_URL` | OpenAI-compatible chat endpoint | Provider documentation |
| `LLM_MODEL` | Chat model name | Provider dashboard |
| `LLM_API_KEY` / `GEMINI_API_KEY` | Chat provider secret | Provider dashboard; never commit |
| `TWILIO_ACCOUNT_SID` | Twilio account identifier | Twilio Console |
| `TWILIO_AUTH_TOKEN` | Twilio signing/API secret | Twilio Console |
| `TWILIO_PHONE_NUMBER` | Twilio sender number for SMS | Twilio Console > Phone Numbers |
| `VOICE_STATE_SECRET` | Secret for signed IVR action tokens | Generate a long random secret |
| `VOICE_BASE_URL` | Public backend origin used in TwiML actions | `https://<service>.onrender.com` |
| `TTS_PROVIDER` | Optional TTS provider name | Your TTS provider; leave empty for Twilio `<Say>` |
| `TTS_API_URL` | Optional TTS HTTP endpoint | Your TTS provider documentation |
| `TTS_API_KEY` | Optional TTS secret | Your TTS provider dashboard |
| `TTS_VOICE_EN` / `TTS_VOICE_TA` | Optional voice identifiers | Your TTS provider documentation |
| `VOICE_AUDIO_PUBLIC_URL` | Public URL for cached MP3 files | `https://<service>.onrender.com/voice-audio` |

`DATABASE_URL` and generated audio/cache files use Render's ephemeral
filesystem. The application rebuilds PIN data at startup, loads the model
from the repository, and pre-warms preset-city cache/audio. Use a persistent
disk or external cache if durable cache retention is required.

## Startup sequence

On every process start the backend:

1. Loads and validates the rainfall model into memory; incompatible/missing
   artifacts fail closed to forecast-only behavior.
2. Creates/seeds the local PIN table from `scripts/load_pincodes.py`.
3. Pre-generates configured fixed phrase audio when TTS variables are set.
4. Starts preset-city insight warming and the 15-minute stale-while-revalidate
   refresher.

## Local run

```powershell
cd backend
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
python scripts/load_pincodes.py
uvicorn app.main:app --reload --host 0.0.0.0 --port 8000
```

Health check: `http://localhost:8000/health`.

## Testing and IVR simulation

```powershell
cd backend
pytest -q
python scripts/simulate_call.py --pin 600001
python scripts/simulate_call.py --city-fallback
python scripts/benchmark_voice.py
```

The benchmark reports local application latency for warmed DTMF menu
requests. It does not measure carrier audio delivery or cold external API/TTS
latency.

## Twilio webhook URLs

After deploying, replace `<RENDER_SERVICE_URL>` with the exact HTTPS origin
shown by Render, for example `https://mazh-ai-api.onrender.com`.

Configure the Twilio phone number's **A Call Comes In** webhook as:

```text
POST https://<RENDER_SERVICE_URL>/voice/welcome
```

The application returns signed action URLs for the rest of the call. The
following endpoints are the complete webhook surface and should be reachable
through POST:

```text
POST https://<RENDER_SERVICE_URL>/voice/welcome
POST https://<RENDER_SERVICE_URL>/voice/language
POST https://<RENDER_SERVICE_URL>/voice/pin
POST https://<RENDER_SERVICE_URL>/voice/pin-confirm
POST https://<RENDER_SERVICE_URL>/voice/city
POST https://<RENDER_SERVICE_URL>/voice/menu
POST https://<RENDER_SERVICE_URL>/voice/sms-choice
POST https://<RENDER_SERVICE_URL>/voice/sms-number
```

Only `/voice/welcome` is pasted into the inbound-call field; the remaining
URLs are generated by the service and must not be hard-coded in Twilio.
Twilio signature validation uses the public URL reconstructed from
`X-Forwarded-Proto` and `X-Forwarded-Host`.

## Deployment checklist

- [ ] Push the repository, including `backend/models/rainfall_model.joblib`.
- [ ] Create the Render Blueprint from `render.yaml` in the Singapore region.
- [ ] Set `ENV=production`, `HOST=0.0.0.0`, `CORS_ORIGINS`, and `ML_ENABLED=true`.
- [ ] Set `VOICE_STATE_SECRET` to a long random value.
- [ ] Set Twilio SID, auth token, and sender number in Render secrets.
- [ ] Set `VOICE_BASE_URL` to the final HTTPS Render origin.
- [ ] Set `VITE_API_URL` in Vercel to the same Render origin.
- [ ] Deploy and confirm `GET /health` returns HTTP 200.
- [ ] Confirm startup logs show model preload, PIN load, and preset-city warm-up.
- [ ] Set Twilio inbound webhook to `POST .../voice/welcome`.
- [ ] Make a test call, choose English/Tamil, enter `600001#`, confirm with `1`,
  and test menu options `1`, `4`, and `5`.
- [ ] Verify Twilio signature rejection for an unsigned production request.
- [ ] Confirm SMS failure returns a spoken message and returns to the menu.
- [ ] If using custom TTS, verify `VOICE_AUDIO_PUBLIC_URL` serves an MP3 over
  HTTPS; otherwise leave TTS variables empty and use Twilio `<Say>`.
- [ ] Monitor Render logs for latency, provider timeouts, and fallback usage.
